# struct-v2 — the model designs the deck

**Branch:** `struct-v2`. An experiment. If the output is worse it is deleted; if it is better it ships.

## The shape asked for

```
1  READ      the merchant's options
2  DESIGN    one model call, whole deck. Decides EVERYTHING:
             which sections · what order · how many · signature ·
             dark · padding · motion · which band may carry a photograph ·
             what goes inside each band
3  BUILD     per page, materialise the plan into real elements and copy
4  EXPORT    toPagefly — unchanged, 0 tokens
```

## What this changes vs today

| Decision | Today | struct-v2 |
|---|---|---|
| Which sections, what order | `decideStructure` (model) or the arc | stage 2 (model) |
| How many sections | arc length, or 5–10 vetted | stage 2 (model) |
| Signature | `finish()` — rule off the arc | stage 2 (model) |
| Dark bands | `finish()` — `draw(seed, 41, …)`, a dice roll | stage 2 (model) |
| Padding | `finish()` — `i % 3 === 2` | stage 2 (model) |
| Which band may carry a photograph | `finish()` — hero + furthest statement band | stage 2 (model) |
| Motion | `finish()` — from the vertical register | stage 2 (model) |
| What is inside each band | stage 3 only | stage 2 writes a brief, stage 3 builds it |

## The two facts this design has to live with

**Stage 3 is not cheap, and the plan does not make it cheap.** `scripts/phase3-cost.ts` measured exactly this: a page built to a fully-specified order. The recorded result (`structure.ts:48`) is that *a precise spec costs MORE reasoning than a free choice*. Do not budget for a saving here. The reason to run this experiment is page quality, not cost.

**One completion cannot hold N pages of element detail.** A page's design tree measured 26,726 tokens; the ceiling is 48,000. So stage 2 emits a **band-level plan** — pattern, rhythm, and a prose brief per band — not element trees. Ten pages of that is a few thousand tokens and fits comfortably.

## The seam

`designServer.ts:429` already reads:

```ts
input.structure?.length ? orderFromSlots(...) : planPage(...)
```

Stage 2 emits the same `Order` shape those two produce, so `orderLines`, the skill slicing, `audit`, the exporter and the mockup renderer are untouched. Three deciders, one seam.

## Guardrails kept, and why

The model decides. A `vet` pass afterwards repairs only **structural impossibilities** and logs every repair:

- exactly one signature
- never two adjacent dark bands
- at most two bands with a background
- no background on a `commerce` / `proof` / `utility` band
- 3–12 sections
- pattern ids must exist; the vertical's ban list is enforced
- required pins for the page type are present

These are kept not to overrule the model but to make the experiment **measurable**: the repair log is the number that says how often the model got the rhythm wrong. Without it, "the pages look worse" is a feeling. With it, it is a count.

## Swappable design model

Stage 2 gets its own provider so it can run on a different vendor, model, and key from everything else:

```
DESIGN_PROVIDER=deepseek|anthropic   # default: whatever AI_PROVIDER resolves to
DESIGN_MODEL=deepseek-v4-flash       # default: that provider's default
DESIGN_API_KEY=…                     # default: the provider's usual key
```

Unset = today's behaviour. Set `DESIGN_PROVIDER=anthropic` + `DESIGN_MODEL=claude-opus-5` and stage 2 runs on Opus while stage 3 stays on DeepSeek.

## Off by default

`USE_DECK_PLAN=true` turns it on. Unset, the build runs exactly as it does today — so the branch can be merged and measured before it is trusted.

## How it will be judged

`scripts/baseline.ts` already counts what matters: distinct paddings (≥3), distinct font sizes (≥5), dark sections (≥1). Run it on a deck built the old way, then the new way, and compare. Plus the vet repair count, and tokens per build.
