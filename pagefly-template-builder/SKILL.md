# PageFly Template Builder

Turn a design (image or HTML file) into a working PageFly import. Two output formats:

| Format | When | How it reaches PageFly |
|---|---|---|
| **Clipboard JSON** (`{"pageflyData":[...]}`) | Single section/block | User pastes into a selected element in the editor |
| **`.pagefly` file** | Whole page (multiple sections, fonts, page-level JS/CSS) | PageFly → Pages → Import |

Both are generated by `scripts/pagefly_builder.py`. Never hand-write the JSON — the
builder generates and validates it; hand-written payloads routinely fail in ways the
editor won't report (it renders an empty block and stays silent).

## Workflow

1. **Read the design.** For an image: extract layout structure, exact colors (as rgb),
   font roles (serif headings vs sans body), spacing, and all copy text. For an HTML
   file: parse the CSS `:root` palette and per-component rules — use the *real* values,
   don't approximate. List the sections top-to-bottom before building anything.

2. **Ask what's dynamic.** Product data (price, variants, ATC) must use PageFly product
   elements inside a ProductBox, not static text. Interactivity (calculators, sliders,
   tabs beyond Tabs3/Accordion3) needs a `Custom.HTML` element + page-level `customJS`.
   Confirm product handles/variant names with the user — never invent Shopify handles.

3. **Write a build script** that imports `pagefly_builder` and composes the page from
   its helpers (`H2`, `P4`, `FB`, `BTN`, `icon`, `section`...). Read
   `references/schema.md` FIRST for element vocabulary, required child slots, selector
   support, and breakpoint keys — most paste failures come from violating these rules.

4. **Validate + package.** The builder's `validate()` runs automatically on build; it
   catches duplicate ids, orphan children, double-parented nodes, wrong slot children,
   and style entries pointing at missing items. Then:
   - `to_clipboard(root)` → clipboard JSON string
   - `to_pagefly(page, "name", "out.pagefly")` → import file

5. **Interactive behavior** goes in page-level `customJS` (it IS restored on import —
   confirmed by test). Reuse the patterns in `references/js-library.md` (variant sync,
   count-up on scroll, animated compare bars, cost calculator) instead of writing new
   ones; they are already guarded against double-init, respect prefers-reduced-motion,
   and retry for late-rendered nodes. Wire JS to elements via `data.className` — the
   builder sets real CSS classes from it.

6. **Deliver.** Present the `.pagefly` (or clipboard JSON) plus a one-paragraph note on
   anything the user must supply (image srcs, product handles, variant names, prices).

## Rules that prevent silent failures

These are hard-won from real paste testing — each one broke a payload at least once:

- **One `children` key per node.** A duplicate key means JSON keeps the last one; the
  editor renders the container styled-but-empty with no error. The builder can't produce
  this, but if you ever splice JSON manually, check it first.
- **Type names are exact and versioned**: `Heading2`, `Paragraph4`, `Button2`, `Icon2`,
  `Image5`, `FlexBlock` — one unknown type rejects the *entire* paste, not just that node.
  Full vocabulary in `references/schema.md`.
- **Compound elements have fixed slots** (ProductBox, ProductPrice2, ProductQuantity,
  Accordion3's 4-tier nesting, Tabs3's nav buttons). Don't add or remove slot children;
  the schema reference lists each one.
- **Text elements are fine with `children: []`** — Icon2/Dropcap/CompactButton slots are
  optional. Prefer the light form; it halves node count.
- **`styleData` is raw CSS pass-through** keyed by selector: `&`, `&:hover`, `&::after`,
  `&.is-active`, `&[data-active="true"]`, `& > form`, `& [data-pf-type="X"]` all work.
  Breakpoints: `all` (base) → `laptop` → `tablet` → `mobile`.
- **`--pf-flex-layout-parent-direction` must match the parent's direction at every
  breakpoint** — it's denormalized state; when a parent flips vertical↔horizontal at a
  breakpoint, every child's value must flip with it or sizing breaks.
- **Bars/tracks**: track needs `overflow: hidden`; fill uses `width: N%` +
  `--pf-flex-layout-width: fixed`. Equal-height cards: container `align-items: stretch`
  + card `height: auto` (NOT `fit-content` — that defeats stretching).
- **Liquid safety**: any `{{` or `{%` inside `Custom.HTML` code or customJS gets eaten
  by Shopify's Liquid engine on publish. The builder greps for these; wrap in
  `{% raw %}` only if Liquid output is actually intended.

## What the editor can't do (route around, don't fight)

- JS never runs inside the PageFly editor — only preview/live. Tell the user this or
  they'll report the block as broken.
- No native slider/range input, no computed values → `Custom.HTML`.
- Popups: content is buildable as JSON, but click-triggers are wired manually in the
  editor UI on the Popup element.
- `classGlobalStyling` values (`pf-heading-1-h3`…) are shared theme classes — copy them
  from existing exports if present, never invent new ones.
